01

Overview

  • Problem: metadata search ignores image content; English CLIP + live translation adds latency and loses meaning
  • Goal: real-time search over 1M images that takes Korean queries directly, with automatically built training data
  • Result: 7.8 ms average search, category keywords in Korean queries are recognized
  • System: Django REST API (requests) + PyTorch GPU module (retrieval)

04Image–caption pairs1,028,223 pairs (JSON)
  • Per-category prefix mapping: “a photograph of” (photo), “an illustration of” (illust), …
  • Purpose: consistent embeddings within a category + category keywords in queries (“photo”, “template”) reflected in results
  • English captions translated to Korean with davidkim205/iris-7b
  • Filter rules: repeated tokens · abnormal special characters · Hangul-ratio threshold
  • 1,028,521 real-world industrial images → 293 translation failures + 5 caption failures removed

03

Fine-tuning

  • Pre-trained model: Bingsu/clip-vit-large-patch14-ko (Korean CLIP via knowledge distillation)
  • Limitation: strong in Korean but weak on industrial-domain vocabulary and visual detail
  • Image–caption contrastive learning, training both image and text encoders
  • Image and caption features extracted → L2-normalized → stored in H5 with category labels
04

Search

01Korean queryno translation
02Text encoderfine-tuned model, 768-d
03Cosine similaritytorch.mv over the full DB
04Top-Koptional category filter
  • GPU in-memory: 1,028,223 × 2 (image + caption) × 768 × FP16 ≈ 3.0 GB
  • Loaded once as PyTorch tensors at startup → no disk I/O at query time
  • Two modes: (1) image search · (2) caption search

Retrieval quality (qualitative)

  • Meaning preserved — “a person lying with a dog”: Ours keeps the relation between subjects; AlignCLIP's translation fragments the query into word-level attributes
  • Category-aware — “illustration of the sun setting over the sea horizon”: Ours returns sunset illustrations; AlignCLIP distorts “setting sun” and drops “illustration”

Beyond the paper

Training strategy comparison

  • Setup: LR 5e-6 · batch 32 · 10 epochs · weight decay 0.2 · fixed temperature 0.07 · 9:1 train/val split
  • Evaluation: 100K pairs sampled from the full data by category ratio; Recall@K over all 100K candidates
  • The evaluation set is not separated from training data → read as a relative comparison of strategies, not absolute accuracy

Vector store evolution

  • Faiss (memory only, rebuilt on restart) → Qdrant (HNSW, persistent, metadata filters) → GPU in-memory exact search
  • 1.9 ms Top-K over 1M vectors with no approximation

Groundwork for follow-up: negation

  • CLIP tends to return the negated object for queries like “a mountain without snow”
  • Generated and filtered ~256K negated captions with Qwen2.5-7B-Instruct + vLLM (“… with no passengers”)
