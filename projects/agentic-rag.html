01

Overview

  • Problem: civil servants rotate every ~2 years → skills and hand-over suffer → slow, manual-driven response in emergencies
  • Goal: a “digital colleague” that gives troubleshooting guidance, controls pumps and levels in natural language, and forecasts water levels from data
  • Structure: natural-language command → LLM picks a tool → hardware control / manual search / LSTM forecast
  • Role: team lead — managed the project, designed the whole system, and built it
02

Architecture

  • UI: Streamlit web dashboard (chat · water levels · automation)
  • Model: EXAONE 4.0 served locally with LM Studio (OpenAI-compatible API) → strong Korean, data stays on site
  • Orchestrator: turns language into structured tool calls (JSON) and runs them
  • Hardware: PySerial, Arduino Mega 2560 · relay module · water-level sensor · pump motors
  • Data: PostgreSQL time-series log + pgvector manual embeddings (LangChain loaders · chunking)
  • Prediction: TensorFlow / Keras LSTM
  • Docker Compose deployment, simulation mode without hardware
03

Agent

Agentic RAG & function calling

  • Query Analyzer → Tool Manager → Response Generator; compound requests chain several tools
  • Function calling with a 3-step fallback: tools API → functions API → JSON parsing
  • Final version replaces the LLM tool-selection call with rule/keyword routing → faster, more stable; falls back to manual RAG search
  • The LLM writes the final answer from the tool results (streaming)
  • RAG: manual chunks → BGE-m3-ko embeddings → pgvector search

Autonomous agent

  • Every 10 s: collect level · forecast · pump state → LLM returns a JSON decision → pump control
  • Decision validation · up to 3 retries · allow-list of reservoirs · 4 alert levels

04

LSTM

  • Water levels are non-linear and complex → LSTM for time series
  • Input → LSTM(64) → Dropout → LSTM(32) → Dense(16) → Dense(1)
  • Short-term horizons: 1 m · 5 m · 30 m · 1 h · 6 h
  • Falls back to linear regression / moving average when the model is unavailable
  • Parses time expressions: “in 30 minutes”, “3 p.m.”, “when it reaches 100 m”
05

Results

  • Natural-language hardware control: “turn on pump 2”, “check the current level” → Arduino pump On/Off · live sensor readings
  • Live charts · automatic reports: real-time level graph; questions and actions exported as a PDF report
  • Manual-grounded troubleshooting: answers operating problems with solutions cited from the manual
